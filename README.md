## What I'm Building

### UpcharAI

**An explainable, offline-first clinical decision-support prototype for rural healthcare.**

UpcharAI started as a hackathon project and became a much more involved engineering project. The system combines a deterministic triage engine with a web application designed around unreliable connectivity and the constraints of rural healthcare environments.

Some of the things I worked on include:

- NEWS2-based physiological scoring
- Deterministic clinical red-flag rules
- Explainable triage results
- Role-based access and clinician finalisation
- Local SQLite persistence
- Offline store-and-forward synchronization
- Emergency referral workflow simulation
- Multilingual health-information chatbot
- Automated API, engine, security and regression tests

**Built with:** Python, FastAPI, React, TypeScript, SQLite

[View Repository](https://github.com/ghketan/UpcharAI) · [Live Demo](https://upchar-ai-beta.vercel.app/)

## How I Like to Build

I don't consider a project finished just because the interface works.

I try to understand:

- What problem is actually being solved?
- What happens when something goes wrong?
- What assumptions is the system making?
- How should the data be stored and handled?
- Can another person understand the code later?
- What can be tested instead of simply assumed to work?

I'm still learning these things, but they are becoming a bigger part of how I approach projects.
